# Reflect + follow-ups

Reflect is the per-source chat. It works like Ask, scoped to one source, and after each answer it offers follow-up chips generated by a small follow-up agent.

## Sub-features

- Question box `Ask anything...`, the model picker, and `Clear Chat`.
- Streamed answer, with the search tool steps shown ("Searching for …", "Found N result(s)").
- Follow-up chips under the answer. Clicking a chip submits it as the next question.
- The session persists per user and source (`reflect_session_store`).

## How to get to it (user POV)

Library → a source → sidebar sub-item **Reflect** (`/library/$id/reflect`). The page heading is "Reflect on this source".

## Driving it with Playwright

Scenario: `node run.mjs reflect-followups`. It works in both `VERIFY_LLM` modes.

1. Create a source, go to `/library/$id/reflect`, fill `textbox "Ask anything..."`, and press Enter.
2. Wait for the `<tag> Stubbed answer` text, where `<tag>` is `[fake-llm]` in fake mode and `[stub-llm]` in http mode.
3. Wait for `button "<tag> Tell me more"`. Expect exactly two chips.
4. Click the chip. It appears as a user bubble, and a second answer streams in.

**Proof:**
- screenshots of the chips and of the answer after the chip was followed
- in http mode, `provider-calls.jsonl` shows `"function_call": "FollowUpPrompts"` on `gemini-3.5-flash-lite`

## Gotchas

- **Fixed 2026-09-26:** chips were always empty. `generate_followups` read `response.parsed`, which Jetflow leaves unset after an exit action (the run ends on the tool message). It now parses `response.content`, the same way transcript sectioning does. `compare.sh HEAD~1 reflect-followups` with `VERIFY_LLM=http` shows the base failing.
- Follow-ups are generated for Reflect only, not Ask.
